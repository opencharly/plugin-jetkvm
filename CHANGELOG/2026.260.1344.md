# 2026.260.1344 — fix(catalog): remove phantom methods and pin the invariant with tests

## Summary of changes

Removes three **phantom methods** from the catalog and pins the invariant with tests so it cannot drift again. The validator caught this on the skill PR: the schema advertised methods the plugin cannot act on.

- `schema/jetkvm.cue`: removes `metrics`, `get-settings` (left in the schema **and** in `readOnlyMethods` after their implementations were deleted in an earlier revision) and `session` (in the schema, never dispatched, never refused). A catalogued method with no dispatch is a phantom: an author can write a step the schema accepts that then fails at dispatch, and any skill documenting the catalog misleads an agent dispatching on it.
- `methods.go`: removes the two matching `readOnlyMethods` entries, and **adds the exported production function `NeverAutonomousMethods()`** (a copy of the `neverAutonomous` set) so the invariant test READS the real refusal set instead of restating it (R3).
- `catalog_invariant_test.go` (NEW, 6 tests): pins the invariant in both directions by reading the schema and the dispatcher —
  - `TestSchemaMethodParseCoversTheWholeEnum` — the enum parser sees both the head (`status`) and the tail (`rpc`), so a blank line cannot silently truncate the parse;
  - `TestCatalogHasNoPhantomMethods` — every schema method is dispatched or refuse-before-dispatch;
  - `TestRefusedSetIsRefusedBySafety` — cross-checks `NeverAutonomousMethods()` against `methodSafety`'s real behaviour;
  - `TestNoUncatalogedDispatch` — every dispatched method is in the schema;
  - `TestReadOnlyMethodsAreCataloged` — the read-only allowlist names only catalogued methods;
  - `TestReadOnlyAndRefusedDoNotOverlap` — the classification is a true partition.

**Closes / relates to:** surfaced by `opencharly/layer-charly-check#13`. That skill PR documents the corrected catalog and should land after this one.

**Breaking change + rollback:** `none` for real users — the removed methods were never dispatchable (a step naming them already failed at dispatch). It does tighten `charly box validate` for anyone who authored one of the three, which is the fix. Revert the merge to roll back.
