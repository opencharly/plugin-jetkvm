# 2026.269.1451 — feat(jetkvm): console terminal session, bounded flow, LUKS unlock, boot order

## Summary

Adds the human-in-the-terminal surface to the `jetkvm:` verb, over the shared,
transport-neutral console engine merged in **opencharly/sdk#296** + **#304**
(`github.com/opencharly/sdk v0.2026269.1433`, which this PR requires):

- **`open-terminal` / `run-command` / `close-terminal`** — drive an OPEN shell on
  the controlled machine, reading each command's result by OCR. `run-command`
  supports `sudo`, `expect` assertions, `close_terminal`, and `prompt_anchors`
  (a shell-prompt preflight that refuses to type into a pager/menu/login screen).
- **`luks-unlock`** — enter a disk-encryption passphrase at the initramfs prompt;
  a wrong passphrase FAILS fast.
- **`flow`** — a BOUNDED state machine: continuous OCR-until-condition with NAMED
  outcomes, if/then/else + case/switch, bounded while, **reference-screenshot
  outcomes**, and **auto-resume**. A flow's wall-clock budget is derived from the
  dispatch deadline so it stops CLEANLY before the host's never-hang kill.
- **`boot-order`** — set the UEFI boot order from inside the OS via `efibootmgr`
  (`list` / `next` / `set`).

Implemented ONCE in `sdk/kit` (console_actions.go); this plugin supplies only its
USB-HID `ConsoleTransport` and the CUE→Go decode (R3).

### Schema (SDD) — and the review fixes

- New surface is CUE in `schema/jetkvm.cue`; params regenerated with
  `cue exp gengotypes` + the retag transform (byte-reproducible from the schema;
  verified).
- **Review fix:** the `action:` doc listed `set-audio` as action-bearing, but
  set-audio uses `int_value` (no action). Corrected the doc (and the regenerated
  params comment).
- **Review fix:** `TestSessionMethodsAreMutating` now includes `flow` and
  `boot-order`.
- **Review fix:** added pure decode tests (`sessionTerminalOpen`,
  `sessionBootOrder`) and refactored those decodes out of the `run*` wrappers so
  the param→neutral mapping is unit-locked without a device.
