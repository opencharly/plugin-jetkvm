# 2026.314.0015 — refactor(schema): derive the jetkvm word lists from vocabulary tables

## Summary

Convert the seven inline `|` word unions in `candy/plugin-jetkvm/schema/jetkvm.cue` to the §10.1 S3 vocabulary-table idiom the tree already uses — a `_`-prefixed table, its derived `_…Word` list, and the enum as `or()` of that list: `_button`, `_mediaMode`, `_usbDevice`, `_bootOrderAction`, `_installAction`, `_action`, `_method`, each tagged `@vocab(jetkvm)`.

These are the 92 `union` rows `design/dpat-baseline.tsv` records for this one file — the largest single file in the org census, whose next-largest is 36 (opencharly/opencharly#945; sequence and ordering opencharly/opencharly#950). Each closed set of words now has ONE home, and adding a word is one table row rather than an edit to a disjunction.

Nothing an author or a consumer reads moves:

- the seven accepted word sets are **identical** (3, 2, 6, 3, 3, 18, 71 words), read from the compiled CUE on both sides;
- `params/cue_types_gen.go` is **byte-identical except one stale comment**, so no Go type, field or tag changes;
- the accepted authored surface moved **zero verdicts in either direction** over 228 judged cases.

The two catalog tests also stop parsing the enum's TEXT. A derived enum has no body to parse, so the old reader would have found ZERO methods and left every invariant below it passing vacuously; both now read the SERVED schema through the CUE API (one shared reader), and a new `schema_served_test.go` composes the plugin's own `Describe` reply and compiles the body the host receives. That last one is the load gate `charly box validate` does not provide: a dangling reference inside a served definition is green at plugin load (opencharly/spec#301).

The diff is exactly these six files:

| file | change |
|---|---|
| `candy/plugin-jetkvm/schema/jetkvm.cue` | the seven unions become S3 tables + derived lists; the false "trailing-pipe disjunction" note is replaced by the S3 statement |
| `candy/plugin-jetkvm/params/cue_types_gen.go` | regenerated — one comment changes, every declaration identical |
| `candy/plugin-jetkvm/schema_served_test.go` | new: compiles the served body, resolves the named definitions, and pins the table→list→enum derivation |
| `candy/plugin-jetkvm/catalog_invariant_test.go` | both enum readers move from text parsing to the CUE API |
| `candy/plugin-jetkvm/session.go` | one comment: the generated type's shape is now an inline `or()` over a table |
| `candy/plugin-jetkvm/go.mod` | `cuelang.org/go` moves from indirect to direct (the tests use it) |
